# Rhino 建模已写入、视图收尾失败（2026-11-11）

## 截图可确认的事实

工具顺序为 run_python 完成 → get_viewport_image 完成 → set_camera 完成 → get_viewport_image 完成 → zoom_to_layer 失败。错误为没有与绑定文档唯一匹配的原生 MCP，而非 Python 几何异常或目标图层不存在。因此失败的是后续缩放视图步骤；不可要求用户从头重建已经存在的模型。截图无法提供当时的详细 mismatch 原因，不能声称已从现场日志证明具体哪项指纹不同。

## 已定位的通用代码缺陷与本次修复

- 旧匹配将可变的相机/选择作为每次调用必须相等的文档身份。异步探测期间切换/重绘活动视图会让相同文档误匹配失败。
- 非空文档现在要求完整、计数一致、无重复的对象 ID 集合与原生相等，同时该集合在所有打开的文档中唯一。只在此严格身份可证时，不再要求瞬时相机和选择一致。
- 空文档/旧式指纹保留严格相机/选择/唯一性；相同对象 ID 的文档副本、截断清单、不完整清单、多监听器匹配仍拒绝派发。不会回退到当前 ActiveDoc 或随意使用第一个监听器。
- 原生只读探测后重新读取原绑定文档，减少异步采样过期；仍在每次调用前校验，无基于旧连接盲目信任。
- 匹配失败现在带具体诊断，说明工具尚未派发，不再无论何因都要求手动 MCPStart。
- Chat 在同一轮有真实结构验证通过/有效安全构建提交回执且没有后续未验证几何修改时，若视图整理失败，显示“模型几何已写入，后续视图操作未完成”。原始错误工具保留 error，后续依赖操作取消，不重放建模。没有证据时不宣称几何成功；保存/材质/几何失败不降格为视图警告。
