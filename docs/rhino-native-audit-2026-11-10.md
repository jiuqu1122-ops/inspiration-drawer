## 1. 能直接借鉴的机制，不是万能建模算法

| 本地证据 | 原生行为 | 本项目取舍 |
|---|---|---|
| `Rhino.AI.AgentPrompts.GroundingSteer` | 操作已有模型前主动读取当前文档、选择与画布，不假定旧状态仍有效 | 保持实例+文档绑定，读回实际对象；新文档不继承旧任务 |
| `AgentPrompts.GrasshopperSteer`、`Tools.GH1_SolveTool`、`Tools.GH2_SolveTool` | 建图/求解后读取每个组件的错误、警告与 ID，针对错误组件增量修改 | 不把打开 GH 当完成；保留精确诊断和有界修正，不照搬无限循环 |
| `Tools.RunPythonTool`、`ScriptProjects.RhinoCodeRunScript` | 走 RhinoCode 的 Python 3，并注入 `__rhino_doc__`；返回 stdout、stderr、异常及编译诊断 | 不把 traceback 当成功；错误后区分未执行、已失败和结果未知 |
| `Tools.ToolResult` | 错误类别、消息、指导与附件分开，失败仍保留诊断内容 | 几何错误保留输入路径、孔编号与实测间距；面板直接显示原因 |
| `AgentDispatch`、`TurnUndoCheckpoint` | 每个文档有执行门；一轮任务开启并结束 Undo 记录 | 学习文档级任务隔离；Undo 分组不是异常自动回滚，不能据此重放原脚本 |
| `AgentRunner` | 将对话交给可配置 Agent 会话继续执行工具流程 | 当前任务可用工具必须真实开放，不能先被关键词过滤后再让模型猜有没有工具 |

没有在本次检查的方法中发现“任意图片必然自动生成正确模型”的通用几何求解器，也没有证据证明原生不会出现同样的 RhinoCommon 几何异常。它主要提供工具、明确上下文、结构化错误和 Agent 闭环。静态审计不能证明真实模型成功率。

## 2. 本次实际失败的证据链

从用户本机 Chat 数据库以 SQLite `mode=ro` 读取该轮两次 safe_profile_solids 的参数与回执；未修改聊天记录。

- 第一次：11 项冲突，包括 4 个孔越界/穿过外轮廓，多个壁厚或孔间距不足。
- 第二次：只把 `minWall` 从 6 改成 3，所有轮廓和孔坐标不变；4 个越界孔仍越界，另一处孔间距仍为 1.5，低于要求的 3。
- 因而“只改 minWall”不可能修好相交边界。两次回执均明确 `stage=preflight, documentChanged=false`，这两次没有写入对象。
- 原参考图有不同方向的安装耳、前后支腿及空间连接；单个平面恒厚轮廓不能单凭 IsSolid 就证明完成该三维形态。这里是能力选择和形状理解风险，不应为这张图硬编码几何模板。

该记录只作为错误归因/回归样本，不作为生产形状数据。生产代码没有这张图的坐标、孔数量或零件名。

## 3. Beta.20 本轮改动

1. 对真实零写入预检的修正，检查冲突边界是否真的改变；同一无效计划、只降 minWall 但越界边界不动、直接删孔，均在再次进入内核前给出具体反馈。最多两次有界修正，不无限循环，不重放已提交或结果不明的写操作。
2. 错误回执指向本次输入的 `parts[i].outer/holes[j]` 等字段；给出零件、1-based 可读孔编号、实际间距和要求。Rhino 面板不再只显示“失败”。这不是自动坐标求解器，也不暗改壁厚/孔尺寸。
3. 平面工具明确为可选的专用能力；已识别的 Loft/Sweep/Pipe/SubD/分叉有机体流程不会被强制扁平化。不声称仅靠提示约束就能验证照片级形似。
4. 有可用图片参考时开放真实图片工具，由模型按语义选择；对明确的优化/改比例/换风格等需求提供执行兜底。补发参考图可承接上一条用户需求，无需重复“出图”。最新的“仅分析/先别出图/等我发图”有优先级，不能因旧出图指令强制付费生成。截图用于代码修复不会被自动当成修图。
5. 新对话用第一条用户需求的首句命名；旧自动编号标题只读查询最早用户消息用于显示，不改 ID、文档绑定、聊天内容或历史归属。空对话显示“新对话”，手工标题保留。

## 4. 必须继续覆盖的失败矩阵

| 阶段 | 常见失败 | 允许的处理 | 禁止的捷径 |
|---|---|---|---|
| 理解与选路 | 把空间分叉体看成板件、把图像修改当文字讨论 | 使用参考和上下文选择能力，核对目标特征；开放可用工具 | 只认特定口令、用单个平板假装还原三维 |
| 参数/脚本预检 | 空参数、API 类型/参数数量不符、未闭合/自交曲线 | 执行前返回精确诊断，有界重写尚未执行的输入 | 把无效参数原样重发 |
| 几何内存构建 | 孔越界、嵌套/相交、壁厚不足、区域不唯一、实体失败 | 改真实冲突字段并重新验证，保留特征和约束 | 降容差、删孔、吞掉 Boolean 异常来报成功 |
| GH 求解 | 组件找不到、连线错误、组件 Error/Fault | 读实际组件 ID/诊断，增量修正并复验 | 清空整个已有图、重复创建图、只打开 GH 就结束 |
| 文档提交 | AddBrep 失败、部分写入、文档关闭/切换 | 读回当前绑定文档，保留已完成结果，报告未知状态 | 将异常当“没执行”，自动重放整个脚本 |
| 传输/宿主 | 断线、超时、运行库不兼容 | 分清已确认未执行与未知结果；仅明确安全路径续接 | 超时后猜测无副作用、排队重复建模 |
| 完成核验 | 零几何增量、开放曲面误当实体、形状不符 | 检查真实对象/拓扑/尺寸和视图；区分结构与外观 | 用成功回执或 IsSolid 等同于任务完成 |

## 5. 验证边界

最终测试与构建结果以发布目录的 `VERIFICATION.json` 和日志为准。本轮没有重放用户旧任务、调用付费图像服务、修改当前 Rhino 模型或覆盖正在运行的安装。自动化使用合成 Provider/IPC/内存数据库与回归输入；真实模型视觉还原、真实 Provider 的修正质量以及升级后的 GUI 联调不能被这些测试替代。仍可能遇到新几何或宿主错误；通用修复的目标是让它们可归因、可安全续接并且不假报成功，而不是承诺任意需求必然成功。
